# 发布与私有官网的配合

本仓库只产出静态网页。生产认证、同源 API 代理和原邀请码落地页由服务维护者管理。

## 构建

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm run build
```

构建固定 base 为 `/invite/`。产物中 `index.html` 和 `assets/` 应分别发布为 `/invite/index.html` 与 `/invite/assets/`。`pnpm run preview` 只预览静态产物，不提供虚拟接口；需要完整演示用 `pnpm run dev`。

## 发布边界

- 开发者提交 PR；维护者审核、合并，记录待发布 commit，再在可信环境构建。
- GitHub Actions 只执行检查，不包含 SSH、生产凭据或自动发布。
- 维护者先备份线上邀请中心和相关配置；仅更新邀请中心目录。
- 私有官网发布必须保留 `/invite/`；邀请中心发布必须保留官网根目录、旧邀请码落地页、API 代理及下载目录。
- 不将本仓库 dist 同步到官网根目录，不对整个官网执行删除式同步。
- 生产 `/invite/` 提供本页面；`/invite/<邀请码>` 仍提供原邀请落地页，两者路由不能混淆。静态资源必须优先按真实路径提供。
- 前端继续请求同源 API。不要更改 Cookie、Origin 校验或把生产用户请求代理到个人服务器。
- 验证页面和资源 200、安全响应头、未登录接口 401、旧邀请链接、官网首页；真实账号联调仅用维护者授权的测试账号。
- 验证失败恢复备份。回滚前端不回滚数据库、不覆盖服务器环境配置。

## 后端变更

兼容性新增先发布后端，再发布使用新字段的前端。破坏性变更先约定版本和迁移窗口；不要通过独立合并两边 PR 假定上线同步。
